# Amazon Connect Call Recording & UK GDPR Consent Persistence

This directory contains the AWS deployment assets and documentation for post-call recording ingestion and ICO/GDPR-compliant IVR consent persistence for **VoxFlow Voice Agent**.

---

## 1. Architecture Overview

```
 Caller
   │ (inbound call)
   ▼
Amazon Connect Instance (eu-west-2, London)
   │
   ├─► Connect Contact Flow (`connect-contact-flow-uk.json`)
   │     ├─► Plays UK GDPR recording notice
   │     ├─► Captures caller consent response via Lex V2 Bot (`$.Lex.InputTranscript`)
   │     ├─► Sets IVR Recording Behavior:
   │     │     ├─ [Consent Granted]: `RecordedParticipants: ["Agent", "Customer"]`, `IVRRecordingBehavior: "Enabled"`
   │     │     └─ [Consent Refused]: `RecordedParticipants: []`, `IVRRecordingBehavior: "Disabled"`
   │     └─► Updates Contact Attributes:
   │           ├─ `consent_granted`: "true" | "false"
   │           └─ `consent_recorded`: "true" | "false"
   │
   ▼ (call terminates)
Connect writes recording (.wav/.flac) to S3 bucket (SSE-KMS encrypted)
   Path: `connect/<instance>/<yyyy>/<mm>/<dd>/<contact-id>/<file>.wav`
   │
   ▼ (S3 Event: `s3:ObjectCreated:*` with prefix `connect/`)
AWS Lambda: `VoxFlow-Recordings-Handler` (`deploy/aws/s3_recordings_handler.py`)
   │
   ├─► 1. Extracts `contact_id` from S3 object key
   ├─► 2. Calls `connect:GetContactAttributes` to retrieve `consent_granted` & `consent_recorded`
   ├─► 3. Tags S3 object with `voxflow:consent`, `voxflow:recorded`, `voxflow:retention-until`, `voxflow:contact-id`
   └─► 4. HMAC-POSTs payload to VoxFlow API `/api/connect/recording`
         │
         ▼
VoxFlow API Server (`POST /api/connect/recording`)
   │
   ├─► `routes/recording.py` validates `x-voxflow-signature` and timestamp
   └─► `services/recording_service.py` executes persistence transaction:
         ├─ Stores `Call.recording_url`, `Call.recording_s3_key`
         ├─ Stores `Call.consent_granted`, `Call.consent_recorded_at`
         ├─ Builds immutable audit evidence `Call.consent_evidence_ref`
         └─ Upserts `RecipientCampaignPreference` consent status for the caller's E.164 phone
```

---

## 2. Why S3 Post-Call Delivery (vs KVS)

- **Post-Call Delivery**: Amazon Connect's native architecture delivers the encrypted recording file directly to S3 upon call termination.
- **24-Month Attribute Retention**: Contact attributes written by `UpdateContactAttributes` remain accessible via `connect:GetContactAttributes` for ~24 months.
- **Zero Real-Time Overhead**: Audio ingestion does not require real-time Kinesis Video Streams WebRTC bridges when post-call compliance archival is needed.
- **Automatic Lifecycle Rules**: S3 object tagging (`voxflow:retention-until`) allows automatic S3 Lifecycle deletion according to retention policies (default: 30 days).

## 3. Contact Flow Attribute Mapping

| Contact Flow Block | Attribute Written | Values | Description |
| :--- | :--- | :--- | :--- |
| `PersistConsentTrue` | `consent_granted` | `"true"` | Caller consented to quality/training recording |
| `PersistConsentTrue` | `consent_recorded` | `"true"` | Consent decision recorded |
| `PersistConsentFalse` | `consent_granted` | `"false"` | Caller opted out of call recording |
| `PersistConsentFalse` | `consent_recorded` | `"false"` | Recording disabled |

## 4. Immutable Audit Trail Format

The consent evidence reference generated by `services/recording_service.py` follows the format:
```
connect:<region>:<instance_id>:<contact_id>:consent=<granted|denied>:recorded=<yes|no>:at=<ISO-8601-UTC>
```
Example:
```
connect:eu-west-2:b3a97cf1-4567-4890-abcd-1234567890ab:f948a31e-4581-432d-9472-887192348512:consent=granted:recorded=yes:at=2026-09-04T06:15:00.000000+00:00
```
This evidence string is immutable once set and provides an auditable chain of evidence for UK Information Commissioner's Office (ICO) and GDPR Article 6 compliance.

## 5. Deployment Guide

### Step 1: Create IAM Role & Policy
1. In the AWS IAM Console (or CLI), create a role for the Lambda function.
2. Attach `deploy/aws/recording_lambda_iam_policy.json` (replacing `<ACCOUNT_ID>` and `<CONNECT_INSTANCE_ID>` with your AWS Account ID and Connect Instance ID).

```bash
aws iam create-policy \
    --policy-name VoxFlowRecordingsHandlerPolicy \
    --policy-document file://deploy/aws/recording_lambda_iam_policy.json
```

### Step 2: Deploy Lambda Function
1. Create a Lambda function `VoxFlow-Recordings-Handler` in `eu-west-2`:
   - Runtime: Python 3.12 or 3.14
   - Architecture: arm64 or x86_64
   - Memory: 256 MB
   - Timeout: 60 seconds
2. Upload `deploy/aws/s3_recordings_handler.py` as `lambda_function.py`.
3. Set environment variables:
   - `VOXFLOW_API_URL`: Base URL of your VoxFlow API (e.g., `https://api.yourdomain.com` or ECS internal/public endpoint)
   - `VOXFLOW_SECRET`: Shared secret matching `CONNECT_LAMBDA_SECRET` on your server
   - `CONNECT_INSTANCE_ID`: Your Amazon Connect Instance ID
   - `CONNECT_REGION`: `eu-west-2`
   - `VOXFLOW_RECORDING_RETENTION_DAYS`: `30`

### Step 3: Configure S3 Event Notification
On the Amazon Connect S3 storage bucket:
1. Navigate to **Properties** -> **Event notifications** -> **Create event notification**.
2. Event types: `All object create events` (`s3:ObjectCreated:*`).
3. Prefix: `connect/`
4. Destination: Lambda function -> `VoxFlow-Recordings-Handler`.

### Step 4: Configure S3 Lifecycle Rule
Create an S3 Lifecycle rule to expire objects based on tags:
- Filter: Tag `voxflow:consent` exists OR Tag `voxflow:retention-until` exists.
- Action: Expire current versions of objects after 30 days.

## 6. Database Verification & Ingestion Endpoint

- **Endpoint**: `POST /api/connect/recording`
- **Authentication**: HMAC-SHA256 signature (`x-voxflow-signature`) + timestamp (`x-voxflow-timestamp`)
- **Database Schema**:
  - `calls.recording_url`: `s3://<bucket>/<key>`
  - `calls.recording_s3_key`: `<key>`
  - `calls.consent_granted`: `1` (consented) or `0` (denied/unconsented)
  - `calls.consent_recorded_at`: Timestamp when consent decision occurred
  - `calls.consent_evidence_ref`: Immutable audit trail string
